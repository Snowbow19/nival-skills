# Scope and Process Analysis

Scope: interaction reference cards that combine an operable example, terminology, an AI instruction, and use cases. Button design is handled by Nival Button Skill.

## INVARIANT

| Step or principle | Why it matters |
| --- | --- |
| Read the sketch and confirm unclear details | Preserve the intended information structure rather than inventing another one. |
| Tie the lesson to a familiar, working interaction | Let readers observe the effect instead of relying on an illustration alone. |
| Pair an accessible name with the correct technical term | Help readers connect what they see with what they can request or implement. |
| Verify visual-reference provenance and version | Avoid teaching an inaccurate or outdated appearance. |
| Normalize visible artwork bounds and resolution | Transparent padding and low-resolution images can defeat correct CSS alignment. |
| Use concise, precise AI instructions | Avoid both unnecessary jargon and vague conversational phrasing. |
| Make representative examples operable | A category list does not demonstrate how the interaction is used. |
| Remove redundant containers | Preserve hierarchy without making every item another card. |
| Align comparable samples without erasing semantic differences | Improve scanning while retaining the distinction between links, cards, and buttons. |
| Iterate within the requested scope and verify the changed behavior | Preserve accepted work and distinguish observed success from assumptions. |

## VARIABLE

Defaults and decision rules are specified in the Inputs table in SKILL.md. They cover topic, audience, language, terminology, layout, style, main scenario, reference visuals, platforms, instruction wording, use-case count, sizing, and delivery. Defaults are starting points, not requirements inherited from one card.

## INCIDENTAL

- The specific concept `cursor: pointer` and its exact instruction sentence.
- The travel-project scene, mountains, coffee shop, river walk, and bookstore.
- Mac and Windows as this card's relevant platform pair.
- The specific OS version, asset files, SVG path, and illustration colors.
- The original blue wrapper and its particular removal.
- The final three samples, their exact labels, horizontal row, and measured dimensions.
- The local server port, file paths, and screenshot names.

These facts belong to the example, not general rules.

## Adaptation Defaults

1. The intended reusable format is an interaction knowledge card, not every kind of UI widget.
2. Default previews remain local; publication is a separate requested action.
3. Chinese is the current audience language; bilingual bold keywords are used when they help explain technical terminology.
4. Platform comparisons are conditional, not a requirement for every card.
5. Use-case count and arrangement follow the teaching need; three horizontal samples are not a permanent template.

## Limits

The two alternative cards are reasoned examples only. They were not implemented or interaction-tested for this draft. This skill is separate from Nival Button Skill.
